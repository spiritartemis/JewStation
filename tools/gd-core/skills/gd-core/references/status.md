# 查进度与播报（读侧 SOP）

> 归属：`gd-core` skill 的**读侧**分支（写侧＝建账/认领/交件/验收/结版，见 `workflow.md` / `discipline.md`）。
> 查进度 = **一条命令** + **固定五段**。不要多点探查。

## 何时加载

- 用户问：进度 / 到哪了 / 下一步 / 交接 / 现在该干什么
- **每次新工作开始前**（尤其换了会话、隔了几天）
- 收工前（改跑下面的「收工三问」）

## 第一步（唯一取数动作）

```bash
gd brief                   # 一屏五段
gd brief --json            # 机器面（brief_version: 1，drift 带稳定 code）
gd brief --full            # 展开已达成里程碑明细
gd brief --section next    # 单段取（上下文紧时）
gd brief --no-git          # 无 git 的宿主（不报未推送 / 未提交）
```

core-only 环境用 `gd-core brief`（同一实现、同一输出）。

## 五段怎么读

| 段 | 回答 | 读法 |
|---|---|---|
| **坐标** | 我在哪 | 五级链 `里程碑 → 版本 → 子版 → 需求 → 任务`；第一段就是当前位置 |
| **鸟瞰** | 全局进度 | 段首一行是全板三组计数（里程碑 achieved/总 · 需求 · 任务）；下面**一行一张里程碑**：`标记 id  别名  定位  需求 done/总`（不用竖线，列按显示宽度对齐）。`✅` = 已达成、`▸` = 进行中（带任务数与逾期/剩余）；已达成超出上限时按**优先隐藏结版最早的**折叠，折掉几张在段首下一行点名 |
| **下一步** | 直接可执行 | 顺序即优先级，每条带可复制命令 |
| **漂移** | 账上的矛盾 | `⚠` 先看（可能丢工作 / 口径冲突）；折叠行里是 info 级提醒 |
| **上次** | 衔接记忆 | 同任务的连续事件已合并成一行（`claim+progress+handoff` 不会占三行）；只留最近 **3 条**、每条一行（时间 / 对象 / 事件 / 说明，无表头行） |

## 呈现（固定格式，不许自创排版）

按五段顺序转述，**不改顺序、不合并段落** —— 固定格式让今天和下周的简报能直接对比：

1. 首段给坐标（一句话说清「在哪」）
2. 中间给鸟瞰 + 下一步 + 漂移
3. 末段给「上次」；漂移里**要人拍的事**（结版 / 认领版本线 / 挂里程碑）集中点出来
4. 数字照抄（账上 `23/28` 就写 `23/28`，不换算百分比、不四舍五入）
5. 漂移里的 `建议` 命令原样给出，别自己改写
6. 没有的段直接跳过，**不要写「暂无信息」**

详细模板与正反例见 `references/present.md`。

## 三条禁则

1. **不许多点探查**：查进度只跑 `gd brief`，最多再补 2 条 `gd req status <id>` / `gd task show <id>`。
   **不许**跑 `req list` / `task list` / `board` / `core roadmap` 的全量面 —— 实测一次全量探查 =
   48 次命令 / 约 48 KB 输出 / 2–3 分钟，而 `brief` 是 1 次 / 1.9 KB / 0.4 秒。
2. **不许手读账文件**：`.git/gdtwork/**` 下的 `*.yaml` / `*.jsonl` 一律不读。账口径只在 `gd` 里算一次；
   手读等于造第二套口径，而且必然漏掉派生规则（需求派生态、子版结版、依赖闸门都是算出来的）。
3. **查询面不写账、不跑门禁**：不 `gd core roadmap --write`、不 `gd sync`、不跑 `contract check` / e2e /
   `ui-check`。门禁属**收工面**，见下。

## 收工三问（与查询面分开）

1. **改动面是什么** → 按 `AGENTS.md` §2 定门禁档（T-UI 类 → `ui-check --changed`；动 CLI / 状态机 /
   验收 / 账目 / producer 契约 → `contract check --scope all` + 对应 e2e）
2. **跑对应档**（不是「全都跑」也不是「都不跑」）
3. **交件带证据**：`gd handoff <任务id> --done … --artifact <件>` —— 交件口径见 `workflow.md` §3.1
   （验收人常是另一个会话，只看得见账和代码）

## 扩展新的查询数据面

`brief` 只是「查询族」的第一条。要加新内容，按三条轴走 —— **不要新开一条散装命令**：

| 扩展 | 怎么加 | 依赖层 |
|---|---|---|
| **加一段** | `lib/brief.mjs` 的 `BRIEF_SECTIONS` 加一项 + 命令壳 `--section` 白名单 + 渲染 | core |
| **加一条漂移判据** | `DRIFT_RULES` 加一行数据（`code / level / hit / text / cmd`），**零渲染改动** | core |
| **加外域数据**（producer 健康 / 注册项目） | **不改 core**：app 层聚合 `gd brief --json` 的输出补肉（`--with-*` 形态） | app |

细节见 `references/expand.md`。

# 简报怎么转述给人

> 目的：**同一份数据，每次长得一样**。固定格式让用户不用重新学怎么看，也让今天的简报能和上周的直接对比。

## 模板（五段，顺序不许改）

```
📌 <板id> · <里程碑名>（<id>）· <今天到期 | 剩 N 天 | 逾期 N 天>

坐标   <m-x> → <x.y> → <x.y.z> → <R-…> → <T-…>
       <一句话说清这是什么活>

鸟瞰   全板 里程碑 a/b   需求 c/d   任务 e/f
       +x 张已达成（折叠：优先隐藏结版最早的）
       ✅ <m-1>  <alias>  <定位>  <done/total>
       ▸ <进行中的里程碑>  <alias>  <定位>  <done/total> · 任务 <done/total> · <逾期 N 天 | 剩 N 天>
         <版本条：只列未结版版本>

下一步 ① <任务id> <做什么>  → <可复制命令>
       ② …
       ③ …

漂移   ⚠ <账上矛盾>（要人拍 / 可能丢工作）
       建议  <命令>

上次   <MM-DD HH:mm>  <任务/需求id>  <事件种类>  <一句话>
       <MM-DD HH:mm>  <任务/需求id>  <事件种类>  <一句话>
       <MM-DD HH:mm>  <任务/需求id>  <事件种类>  <一句话>
```

（「上次」只留最近 3 条、每条一行、无表头行，且排最末；简报不代跑门禁、也不代点名门禁命令。）

## 五条硬规则

1. **数字照抄**。账上写 `23/28` 就写 `23/28`；不换算 `82%`、不四舍五入、不把「任务 61/75」简化成「任务过半」。
2. **不合并段**。即使某段只有一行也不要并进别的段——段名本身是导航。
3. **缺段跳过，不写占位**。没有漂移就整段不出，不要写「漂移：无」凑结构。
4. **命令原样给**。`建议` 里的 `gd line claim 1a` 不要改写成「你可以试试认领开发线 1a」。
5. **要人拍的事集中点名**。结版 / 认领开发线 / 冻结发版 / 挂里程碑这类**只能人决定**的，集中在漂移段末尾点出来，
   别混在「下一步」里让人以为是自动能干的。

## 正反例

### 反面（常见坏写法）

> 我看了一下，项目整体进展不错，需求完成度挺高的。m-4 还有几个需求没做完，
> 开发线 1a 和 1b 还在进行中。另外之前的一些改动好像还没有推送。建议先看看还有什么要做的。

问题：① 全是形容词没有数字 ② 没说「上次干到哪儿」③ 「好像还没有推送」= 没验证就报 ④ 「建议先看看」= 没给命令。

### 正面

> **坐标**：m-1a（开发线）/ R-gm-1a-0（待办）/ T-gm-1a-0-01（执行中）；对外版本 0.70（draft）
>
> **鸟瞰**：全板 里程碑 4/5 · 需求 184/184 · 任务 477/477
> — m-1 `self-host` 84/84 · m-2 `app-agent-ai` 28/28 · m-3 `decision-layer` 19/19 · m-5 `gd-agent` 19/19 已达成，另有一张 ▸ 进行中的 m-4 `req-order` 需求 34/34、任务 92/92。
>
> **下一步**：① T-gm-1a-0-01 `gd work start T-gm-1a-0-01`（你已占用）② T-gm-1a-0-02 文案收口
>
> **要你拍**：① m-4 线上需求已全验收 → `gd milestone reach m-4 --confirm m-4` ② 对外版本 0.70 成员已齐 → `gd release freeze 0.70 --evidence "回归证据"`
>
> **注意**：主仓 5 个提交未推送。
>
> **上次**：10-25 02:38 T-gm-B000037-02 交件并通过验收（work-isolate-e2e 87 项）。

## 上下文紧的时候怎么省

优先级：`坐标` + `下一步` > `漂移(warn)` > `上次` > `鸟瞰` > `漂移(info)`。

要更省就直接单取：

```bash
gd brief --section next      # 只问「我现在该干什么」
gd brief --section coords    # 只问「我在哪」
gd brief --section drift     # 只问「账上有什么不对」
```

**不要**为了省上下文去跑 `req list` / `task list` 全量——那比整份 brief 还大 10 倍以上。

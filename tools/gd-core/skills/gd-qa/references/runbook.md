# 跑测 SOP（runbook）

顺序是固定的：**基线 → 沙箱 → 逐例 → 判账 → 归因 → 出件**。
任何一步跳过，结论都要打折——最常见的是跳「基线」：契约本来红着，后面所有红都归错因。

## 0. 基线（跑测前，只读）

```bash
gd brief                          # 这条线到哪了（五段只读）
gd contract check --scope all     # 数据 / 文档 / 废弃词 / 决策：本来绿不绿
```

- `--scope all` 本来就红 ⇒ 记进基线，后面看到同源红直接标 `expected`（已知基线），不重复计缺陷。
- 同一批 `*-e2e.mjs` 先跑一遍，作为「机检层基线」写进 `runs.md`。

## 1. 沙箱：三选一，按用例需要选最便宜的

| 形态 | 怎么搭 | 适合 | 代价 |
|---|---|---|---|
| **纯账沙箱** | 临时目录 `git init` + 手写 `<repo>/.git/gdtwork/{board.yaml, reqs/index.yaml, reqs/<id>/task-list.yaml}` | 只动账的命令（`req context` / `req acceptance` / `req dep` / `task show`） | 最小，秒级 |
| **CLI 闭包沙箱** | 拷运行时目录进沙箱再跑 CLI（清单与拷贝函数：`scripts/lib/sandbox.mjs`） | 需要 CLI 自定位到沙箱、验落地路径/安装行为 | 拷一份，秒级 |
| **只读回放** | 直接在真板上跑只读命令（`brief` / `task show` / `contract check` / `milestone progress`） | 验读面与渲染、验「跑完不留痕」 | 零代价，但**一个字都不许写** |

沙箱硬规矩：

- 一例一 seed（重跑同一例前先 reset）。要留证据就在 reset 前把账拷出来。
- 跨进程流程（claim → handoff → check、work start → submit → land）必须**固定会话号**（`GD_SESSION`/`PI_SESSION_ID`）。
  缺省会话号带 pid ⇒ 每一步都算「另一个会话」⇒ 占用被自己挡，红出来的假缺陷最费时间。
- 工作区类用例要给独立的 worktree 目录（`--worktree-dir`），别落在真仓的 `.wt/`。
- 板上写的东西默认不提交（`git commit` 未获授权一律不做）；沙箱跑完连目录一起删。

## 2. 逐例执行

一例一屏：命令 → 输出摘要 → **账片段** → 判四问。命令失败时先看它是不是**该失败**（闸门用例的 pass 就是被拒）。

```bash
# 示例：纯账沙箱里判「上下文建议不进账」
gd req context suggest R-tt-001 --path docs/x.md --why "设计稿"
gd req context suggests R-tt-001        # 建议能看到
gd req context list R-tt-001            # 正式条目里不应出现 ← 判据落点
```

## 3. 判账四问（每例都答）

| 问 | 不通过在账上长什么样 |
|---|---|
| 账写了吗 | 该有的块/行不存在（`context:` 整块缺失） |
| 写对了吗 | 形状不符（`kind` 非法 / 时间戳格式错 / 幂等复跑写了第二份） |
| 读面同源吗 | `task show` 显示的状态与 `task-list.yaml` 里的 `status` 打架 |
| 闸门真拦吗 | 该拒的路径 exit 0 且账被改了（最严重的一类：**闸门装饰化**） |

## 4. 归因三层（红必须落到其中一层）

| 分类 | 判据 | 后续 |
|---|---|---|
| **真缺陷** | 设计稿承诺了行为，账/闸门没做到 | 建议开缺陷单（定级 major / minor）；缺陷版本信息走 `--found-in` / `--affects`（不占子版） |
| **设计预期** | 设计稿「明确不做 / 边界」里写着不做或允许空 | 标 `expected` + 贴设计稿出处，不进缺陷 |
| **环境问题** | 沙箱不合规、缺目录、跨进程会话号、CRLF、权限 | 修夹具重跑，**不许记为红**（记了就是把环境债算进质量） |

判「真缺陷」前必须回答一句：**设计稿哪一行承诺了它？** 答不出来 ⇒ 要么是 `expected`，要么是「口径未定」，进人工项。

## 5. 出件

1. 写 `runs.md` 一节（模板见 `case-scheme.md` §5）：表格 + 人工项 + 结论。
2. 回写 `cases.md` 索引表的当前状态（只改状态列与证据引用）。
3. 报给用户：`具备 / 不具备 结版条件` + 理由 + 人工项票号。

## 6. 收工前

```bash
gd contract check --scope all     # 本轮没改代码就确认基线一致；改过就必须重跑
```

跑测若在生产仓动过工具或文档，按仓的升级闸门补跑相应 `*-e2e.mjs`；
门禁口径以仓的 `AGENTS.md §2` 为准，别拿「跑测过了」替代门禁。

# gd-qa

验收 = **判账**，不是看命令有没有 exit 0。

本 skill 只服务一种角色：**懂 gd 账语义的 QA-agent**——两样缺一样就会把「跑了没报错」当成「功能对了」：

| 要有什么 | 用来判什么 |
|---|---|
| QA 手法 | 造环、造撞车、反向对照、显式零值、幂等复跑、故意违规 |
| gd 账语义 | 哪块是事实源、哪条是派生缓存、空值算不算红、`landed ≠ done` |

## 何时加载

- 用户要**验收一条线**（里程碑 / 版本 / 需求）或说「能不能结版」
- 用户要**一套验收用例**，或要**跑测一遍**并出结论
- 用户问「**哪些必须人工验收**」→ 直接读 `references/manual-actions.md`
- 讨论「这条算缺陷还是设计预期」

## 五条铁律

1. **判据落账**——每个 pass 观察点都要落到账上的一行（`index.yaml` / `task-list.yaml` / `events.jsonl` / 板级账）。命令 exit 0 只是前提，不是判据。
2. **沙箱造数据**——真正的板上不造陪跑需求。用临时板（`--main-local`／`GD_BOARD`）或只读回放已结版需求。
3. **空值有预期**——设计稿说了「不强制回填」的字段为空 = 正常，不判红；判红前先在设计稿 §「明确不做 / 边界」里找一遍。
4. **红要分类**——`真缺陷` / `设计预期` / `环境问题` 三选一，不许混成一句「失败」。分类错了比红更难修。
5. **拍板归人**——里程碑 `reached`、需求级验收结论、不可逆动作，一律进人工清单（`references/manual-actions.md`），agent 只出「依据 + 建议」，不代拍。

## 四件套

```
① 立用例（cases 文件） → ② 造沙箱（一次性 fixture） → ③ 逐例跑测判账 → ④ 分人工项 + 出结论
```

产物落哪：`cases.md`（用例集）· 沙箱（临时目录，跑完即删）· `runs.md`（留痕，只追加）· 人工动作票（报给用户）——文件名与字段见 `references/case-scheme.md` §1。

## 判账四问（每例都问一遍）

1. **账写了吗**——该出现的那一行在账里存在吗？
2. **写对了吗**——形状（字段/枚举/时间戳）与设计稿一致吗？幂等复跑会不会写第二份？
3. **读面同源吗**——`gd task show` / `gd req status --board` / 工位页看到的，与账里那行**同一个答案**吗？
4. **闸门真拦吗**——该拒的路径被拒了吗（不是提示，是 exit 非 0 且账未变）？

> 每问「不通过时长什么样」见 `references/runbook.md` §3。

## 最短路径

```bash
gd brief                                  # 先看这条线现在到哪（只读五段）
gd milestone progress <里程碑id>           # 里程碑名下需求与任务完成面
gd contract check --scope all             # 跑测前的基线：契约本身是不是绿的
```

跑完一轮再收口：`gd contract check --scope all`（数据 / 文档 / 废弃词三档）+ 与本线相关的 `*-e2e.mjs`。

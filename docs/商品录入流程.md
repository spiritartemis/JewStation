# 商品录入流程（m-1b · 0.2-09）

> 判据 **B-2.11**：同一套流程可重复录入新商品，字段完整率达标，图片与库存与实物一致。
> 状态：**已可用（文件态）** —— 数据库与后台 Admin 落地后，第 4 步由后台表单替代，其余步骤不变。

## 1. 流程总览

| 步骤 | 做什么 | 谁 | 产出 |
|---|---|---|---|
| 1 | 按采集表整理一款商品的资料与实拍图 | 站长 | `11-首批商品资料采集表.md` 单款明细 |
| 2 | 图片命名与落位（4 图位） | 站长 | `public/img/products/<SKU>-01.jpg` … |
| 3 | 往数据文件追加一条商品记录 | 工程/站长 | `src/data/products.sample.json`（真实数据到位后改名 `products.json`） |
| 4 | 跑校验脚本 | 工程 | 命令行输出：通过 / 不通过 + 缺项清单 |
| 5 | 提交并发布 | 工程 | 站点生效，页脚版本号与更新时间同步递增 |

> 数据库（Postgres）与后台 Admin 属 `08-技术与服务边界决策.md` 的范围，账号待站长提供。
> 在 Admin 落地前，数据文件是唯一数据源；`src/lib/products.ts` 是页面与数据源之间的唯一出入口，
> 切换到数据库时只改这一个文件，页面不感知。

## 2. 字段口径（一次定稿，不得现场发挥）

- 完整口径见 `docs/spec/02-商品数据模型.md`；标签取值见 `docs/spec/03-标签字典与分类规则.md`。
- **标签只能从字典选**：字典的单一真源是 `src/data/tags.json`，新增标签必须先改它并在 03 §8 登记。
- **实物字段不得估算**：材质、尺寸（mm）、重量（g）必须实测。
- **孤品**：`productType = one_of_a_kind`、`stock = 1`，且必填 `oneOfAKindNote` + `handmadeVariation`。
- **图片**：每款 ≥3 张（主图 / 细节 / 佩戴），每张都要 `alt` 与 `width/height`（防 CLS）。

## 3. 图片命名规则

```
public/img/products/<SKU>-01.jpg   主图（正面）
public/img/products/<SKU>-02.jpg   细节
public/img/products/<SKU>-03.jpg   佩戴
public/img/products/<SKU>-04.jpg   包装/尺寸参照（可选）
```

- 比例 4:5，短边 ≥ 1200px；不修色（金属色必须真实，见 `09-素材清单.md`）。
- **禁止用 AI 生成图冒充实拍商品图**（m-1b bootstrap §5）。

## 4. 校验（可重复执行）

```bash
# 校验真实数据文件
node scripts/validate-products.mjs src/data/products.json

# 校验样例数据（缺实拍图只警告）
npm run validate:products
```

覆盖的判据：

| 检查 | 来源 |
|---|---|
| 完整率 8 项（price/stock/productType/materials/dimensions/weight/images/tags） | 02 §5 |
| 孤品 stock ≤ 1 且必填孤品说明 | 02 §3 / 04 |
| 单位固定 mm / g | 02 §4.5 |
| 全站单币种 | 02 §4.6 |
| 图片 ≥3 张且每张有 alt 与宽高 | 02 §4.4 |
| 标签必须存在于字典 | 03 §6.1 |
| title ≤ 60 / seoTitle ≤ 60 / seoDescription ≤ 155 | 02 §4.3 |
| availability 与 stock 派生一致 | 02 §4.2 |

不通过时脚本退出码为 1，并逐条列出缺项 —— **缺项必须登记补齐，不得留空蒙混**（B-1.10）。

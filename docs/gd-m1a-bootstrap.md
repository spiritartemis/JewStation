# gd-m1a-bootstrap — 基础需求确认与基础资源制作

> 里程碑卡 `m-1a` · 线段 `1a` · alias `foundation` · 目标日期 2026-11-06 · 对外版本 V0.1  
> 本文件是这条线的**规格**（什么算做对）；排表（先后顺序）在 `docs/gd-plan-整体版本计划.md`。

## 1. 术语

| 术语                | 含义                                                                                   |
| ----------------- | ------------------------------------------------------------------------------------ |
| 站点地图              | 全站页面清单与层级：首页 / 商品列表 / 商品详情 / 关于我们 / FAQ / 购物车 / 结账 / 订单确认 / 隐私政策 / Cookie 政策         |
| 商品数据模型            | 商品字段的统一定义（英文标题、slug、短文案、详情、价格与币种、图片及 alt、材质、尺寸、重量、过敏提示、保养、库存、商品类型、风格/材质/品类标签、SEO 字段） |
| 标签字典              | 风格 / 材质 / 品类 / 商品类型四类标签的标准命名、可筛选值与维护规则                                               |
| 孤品（One-of-a-Kind） | 手工孤品或限量款，库存恒为 1，成交后不可再售                                                              |
| 可补货款（Restockable） | 流行款，允许补货继续销售，需展示库存状态                                                                 |
| 站长                | 业务方（`owner` 执行体）：提供资料、开户、审核                                                          |

## 2. 场景

1. 工程师按商品数据模型建表、按标签字典打标、按低保真规范搭页面骨架 —— 不需要回头问字段含义。
2. 站长按商品内容模板提交首批 10 款真实商品（售价、库存、类型、材质、尺寸、重量、照片、标签、手工差异说明）。
3. 工程师据此确定选型（前端 / API / 数据库 / 商品管理 / 托管 / 支付 / 物流 / 邮件 / 环境与密钥管理）。
4. 上线前法律与政策复核有可依据的初稿（关于、FAQ、隐私 / Cookie、退换货、手工瑕疵与金属过敏说明）。

## 3. 行为（编号规则与判据）

- **B-1.1 站点地图冻结**：页面清单与导航层级一经确认即冻结；新增页面走变更记录，不得口头追加。
- **B-1.2 商品字段一次定稿**：字段表含类型、必填性、示例值与来源（实物 / 运营）；定稿后任何字段增删必须回写本条。
- **B-1.3 标签去重**：同义标签只保留一个标准名（如 `gold` 与 `golden` 二选一），并登记别名映射；不得出现同物异名。
- **B-1.4 双商品类型共用一套模型**：孤品与可补货款字段完全一致，差异只由 `商品类型` + `库存` 表达，不得为孤品另立字段组。
- **B-1.5 孤品库存 = 1**：孤品记录的库存值恒为 1；任何库存 > 1 的记录不得标记为孤品。
- **B-1.6 状态流转规则成文**：下单锁定 / 付款成功 / 取消 / 退款四个事件各自对库存的影响（锁定、保持、恢复、不恢复）必须逐条写明，并被 `m-1c` 的实现直接引用。
- **B-1.7 移动优先的视觉规范**：低饱和、留白、图片优先；手工款与流行款在卡片/详情上有可辨识的视觉差异；字体、间距、卡片、按钮、克制动效成文。
- **B-1.8 文案分层**：产品文案（商品）与站点文本（政策/FAQ）分开维护；政策类文本标注「待业务/法律审核」，未审核不得进入上线范围。
- **B-1.9 选型成决策记录**：前端、API、数据库、商品管理、托管、支付、物流、邮件逐项给出选择与理由，并给出环境划分与密钥管理方案；密钥只进环境变量或密钥服务，不入仓。
- **B-1.10 商品资料完整率**：首批 10 款商品的必填字段（售价、库存、类型、材质、尺寸、重量、照片、标签）无缺项；缺项必须逐条列出待补，不得留空蒙混。

## 4. 待定（谁能否决）

| 待定项               | 现状                            | 谁能否决 / 定夺                    |
| ----------------- | ----------------------------- | ---------------------------- |
| 目标销售国家/地区、币种、站点语言 | 默认为英文网站，出售地点为欧美及香港新加坡澳门，币种为美元 | 站长（`owner`）定；工程侧只按结果实现，不代选市场 |
| 支付服务商与收款主体        | 这个后续再定                        | 站长定主体与账户；工程侧给集成约束            |
| 数据库与托管            | 数据库与托管还是使用upstash             | 工程侧给建议，站长承担成本与账号             |
| 是否需要多语言（默认英文）     | 需要，但可以后续再开发                   | 站长                           |
| 孤品退款是否回补库存        | 可以补回库存                        | 站长 + 工程侧共同定（影响 `m-1c` 实现）    |
| 首批商品数量（暂定 10 款）   | 可以                            | 站长                           |
| Logo / 视觉参考       | 这个先用你给的默认logo                 | 站长                           |

## 5. 不该发生

- 不在本阶段写页面代码、搭工程脚手架或接第三方 SDK —— 本线只产出「规格与资料」。
- 不臆定支付、物流、税费、退换货规则并写进文档（原文明确：这些不能凭空确定）。
- 不把 AI 生成图当真实商品照片提交首批商品资料。
- 不在未确认字段口径前先建商品表 —— 会造成返工。
- 不把站点文案当成已合规文本 —— 未经业务/法律审核的文本一律带「待审核」标记。

## 6. 暂不涉及

评论与社区 · 会员等级与积分 · 复杂协同过滤 / 向量推荐 · 重型动画 · 密集促销弹窗 · 愿望单登录同步（留待 V1.1 评估）· 支付接入实现（属 `m-1c`）· 页面实现（属 `m-1b`）。

# gd-m1c-bootstrap — 交易模块上线并完成闭环

> 里程碑卡 `m-1c` · 线段 `1c` · alias `checkout` · 目标日期 2026-12-04 · 对外版本 V0.3  
> 排表见 `docs/gd-plan-整体版本计划.md`。

## 1. 术语

| 术语      | 含义                                        |
| ------- | ----------------------------------------- |
| 交易闭环    | 购物车 → 结账/支付 → 订单确认 → 订单状态 → 交易邮件 的完整可走通链路 |
| 库存锁定    | 下单时占用库存，直到支付成功 / 失败 / 取消 / 超时按既定规则释放      |
| 孤品不超卖   | 并发下单下孤品只成交一件（服务端保证，非前端按钮禁用）               |
| 测试订单    | 用支付服务商测试环境完成的验证订单（不产生真实资金流）               |
| 运费 / 税费 | 结账前明确展示的费用，含目的地限制与计算来源                    |

## 2. 场景

1. 访客加购 → 改数量 → 结账 → 支付成功 → 看到订单确认页 → 收到状态匹配的邮件。
2. 孤品只剩 1 件：两人同时下单，只有一人成交；另一人看到售罄。
3. 支付失败 / 用户取消：订单不显示为已付款，库存按既定规则回补。
4. 支付回调重复到达：不产生重复订单或重复扣款。

## 3. 行为（编号规则与判据）

- **B-3.1 购物车可恢复**：刷新后购物车内容按既定策略恢复（会话态或持久态，需写明并一致）。
- **B-3.2 结账要素齐全**：支持 `m-1a` 确认的市场、币种、地址与支付方式；未支持的组合明确拒绝并给出原因。
- **B-3.3 支付回调幂等**：成功、失败、取消、重复回调四类事件各自处理一次，重复回调不重复发货 / 扣款 / 建单。
- **B-3.4 服务端校验库存**：任何下单与支付确认路径都必须服务端复查库存；前端校验只是体验。
- **B-3.5 孤品单件约束**：孤品库存 = 1，并发下单只允许一笔成交；竞争失败者收到明确提示。
- **B-3.6 库存恢复规则来自 `m-1a`**：取消 / 退款是否回补库存严格按 `R-jew-1a-2` 的成文规则实现，不在代码里另立口径。
- **B-3.7 订单确认页口径**：展示订单号、商品、金额、配送信息与后续联系说明；**未确认付款的订单不得显示为已支付**。
- **B-3.8 邮件与状态对应**：下单确认、付款/订单状态、发货通知三类模板齐备；发件域名验证完成；退信策略写明。
- **B-3.9 费用前置可读**：结账前展示运费、目的地限制与适用税费及其来源（规则表 / 服务商计算）。
- **B-3.10 测试订单闭环**：用测试环境完成至少一笔完整订单（含孤品场景），并保留可复核的证据。

## 5. 不该发生

- 不在未确认支付服务商前臆造支付流程或写死假支付页。
- 不用前端隐藏按钮代替服务端库存校验。
- 不在测试环境之外用真实资金做开发自测（除非站长明确授权并知悉）。
- 不把订单状态写死在模板里 —— 状态由订单状态机派生。
- 不在本线做个性化推荐与 Cookie 同意 —— 属 `m-1d`。

## 6. 暂不涉及

订阅邮件 · 推荐 · 愿望单 · 优惠券与促销码 · 多币种实时换算 · 复杂运费分摊（按重量 / 区域细分）· 社区与评价 · 后台可视化报表。

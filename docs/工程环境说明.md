## 2. 依赖安装（本机特殊处理）

本机 `~/.npm` 缓存目录不可写，且对已有 `node_modules` 的删除/重命名会被安全策略拦截，
直接用 `npm install` 会失败。可用流程：

```bash
# 1) 在临时目录全新安装（只创建、不删除）
python3 -c "import os,shutil; os.makedirs('/tmp/jew-deps',exist_ok=True); shutil.copy('<项目>/package.json','/tmp/jew-deps/package.json')"
cd /tmp/jew-deps && npm install --no-audit --no-fund --cache /tmp/jew-npm-cache

# 2) 复制回项目（只覆盖，不删除既有文件）
python3 -c "
import shutil
shutil.copytree('/tmp/jew-deps/node_modules','<项目>/node_modules',dirs_exist_ok=True,symlinks=True)
shutil.copy('/tmp/jew-deps/package-lock.json','<项目>/package-lock.json')
"
```

- `next` 必须 ≥ 15.5.28：15.5.4 存在 CVE-2025-66478，npm 会告警。
- 构建收尾时 Next 会尝试清理临时目录；若被安全策略拦截，只要日志出现
  `✓ Compiled successfully` 与 `✓ Generating static pages (n/n)`，即代表编译与类型检查通过。

## 2.1 构建（本机必读）

本机沙箱对「单回合批量删除」有硬阈值（50 个文件）。`next build` 默认在构建前清空
产物目录（`cleanDistDir: true`），一次清理就会撞阈值，报：

```
[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] {"count":50,"threshold":50,"scope":"turn"}
```

规避方式（已写进 `next.config.mjs`，无需每次手改）：

| 配置 | 值 | 作用 |
|---|---|---|
| `cleanDistDir` | `false` | 构建前不清空产物目录，避免触发批量删除 |
| `distDir` | `process.env.NEXT_DIST_DIR \|\| ".next"` | 可用干净目录做验证构建 |

推荐验证命令：

```bash
NEXT_DIST_DIR=.next-verify npm run build   # 产物进独立目录，.gitignore 已忽略 .next-*/
```

一次完整构建约 **7 分钟**（Compiled 108s + 类型检查 + 15 页静态生成）。只想快速查错时用：

```bash
npx tsc --noEmit        # 约 5 秒，只查类型
```

> 注意：`next build` 会往 `tsconfig.json` 的 `include` 里自动追加 `<distDir>/types/**/*.ts`。
> 用 `NEXT_DIST_DIR` 构建后，记得把该行删掉再提交，否则 tsconfig 会带上 `.next-verify`。


## 3. 版本号与更新时间（硬性约定）

每次改动站点功能/样式/内容并重新发布，必须同步 `src/lib/site.ts` 里的 `version` 与 `updatedAt`，
二者渲染在页脚（`Version x · Updated yyyy-mm-dd`）。**不得只改内容不动这两处。**

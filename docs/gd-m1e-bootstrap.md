# gd-m1e-bootstrap — 运营优化

> 里程碑卡 `m-1e` · 线段 `1e` · alias `growth` · 目标日期 2026-12-31 · 对外版本 V1.1
> 排表见 `docs/gd-plan-整体版本计划.md`。
> **滚动线**：首轮 12-31 收口，之后按真实数据持续迭代（新任务挂同线，线内序号自增）。

## 1. 术语

| 术语 | 含义 |
|---|---|
| 汇总指标 | 匿名可聚合的行为数据（点击、加购、推荐位点击率），用于判断优化项 |
| 愿望单同步 | 收藏数据的跨设备同步（依赖账户体系） |
| 博客 | 保养、搭配思路、手工故事等主题内容，每篇带 SEO 元数据与内链 |
| 优化项可验证 | 每轮优化必须对应一个可观测指标与前后对比，不能凭感觉改 |

## 2. 场景

1. 上线后拿到真实数据 → 检查标签质量与推荐点击 → 发现某类标签下的推荐几乎无点击 → 调整标签与推荐规则 → 复看指标。
2. 发现有访客反复浏览但不收藏 → 评估愿望单是否需要账户同步 → 出评估结论（接入 / 不接入 + 数据合并与隐私流程）。
3. 需要持续内容 → 建博客发布流程 → 出一篇带 SEO 元数据与内链的文章。
4. 页面表现欠佳 → 基于真实数据调整图片、导航、筛选与文案 → 保持动画轻量、避免密集弹窗。

## 3. 行为（编号规则与判据）

- **B-5.1 数据驱动**：每轮优化先有指标，再有改动，再有复测；无指标支撑的改动不记为优化项。
- **B-5.2 规则保持简单透明**：标签与推荐规则可被业务方读懂并手工维护，不引入黑箱模型。
- **B-5.3 博客发布流程可重复**：文章有 SEO 元数据与内链；每篇文章的制作工时单独记（不计入工程工期）。
- **B-5.4 账户同步先评估后实现**：接入前必须写明登录需求、数据合并规则与隐私流程；评估结论无论是否接入都要落账。
- **B-5.5 性能与体验守底线**：优化不得引入重动画或密集弹窗；首屏加载保持流畅。
- **B-5.6 数据不足时不做强推断**：样本不足时只做定性调整并标注「待数据」，不据此下线或改写核心规则。
- **B-5.7 迭代可回退**：每次调整的改动可单独回退，并记录改了什么、为什么。

## 4. 待定（谁能否决）

| 待定项 | 现状 | 谁能否决 / 定夺 |
|---|---|---|
| 是否接入账户体系（注册 / 登录） | 未定 | 站长（`owner`）拍板；工程侧只做评估 |
| 汇总指标的采集口径与保留期 | 依赖 `m-1d` 的同意与持久化设计 | 站长 + 工程侧 |
| 博客主题与发布节奏 | 未定 | 站长 |
| 首轮优化项清单 | 待上线后由数据确定 | 工程侧提案 + 站长确认优先级 |

## 5. 不该发生

- 不在没有数据支撑时改写标签体系或推荐规则的主干逻辑。
- 不引入复杂协同过滤 / 向量推荐（明确不纳入当前版本范围）。
- 不为提高转化加密集弹窗或重动画。
- 不在上线未满一个完整数据周期前把 `m-1e` 判为「已达成」。
- 不把评估任务（1.1-01）当成已实现功能记完成。

## 6. 暂不涉及

社区与评论 · 会员等级与积分 · 多币种定价实验 · 复杂 BI 平台 · 自建推荐模型训练 · 付费投放与广告投放优化（属业务运营，非工程账）。

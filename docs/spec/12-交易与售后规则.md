## 2. 支付：工程侧给的选项与约束

| 方案 | 优点 | 约束 | 备注 |
|---|---|---|---|
| **Stripe** | 卡支付主流、webhook 完整、测试模式好用 | 支持国家有限，需收款主体在其支持列表 | 与 Next.js 集成最直接 |
| **PayPal** | 覆盖广、买家信任度高 | 费率略高、争议流程不同 | 建议做备选 |
| 本地收单（如目标市场本土钱包） | 转化率可能更好 | 集成成本与审核周期更长 | 若主攻单一非英语市场再考虑 |

**工程侧硬要求（无论选哪家）**：
1. 必须支持 **webhook**（支付成功/失败/退款），并处理**重复回调**（幂等）。
2. 必须有**测试模式**，能跑通成功/失败/取消三类路径（`1.0-09` 运营验收要用）。
3. **本站不存储卡号**，卡数据只走支付商托管页/组件（PCI 范围最小化）。

## 3. 运费与税费：口径必须先定

| 口径 | 选项 | 影响 |
|---|---|---|
| 运费 | A 满额包邮（如 ≥ $X 免运费）· B 按地区分档 · C 统一价 | `0.3-06` 实现；影响结账页展示与订单金额 |
| 税费 | A 价含税（含 VAT/GST 展示）· B 价不含税，结账时加 · C 仅本国含税、海外不含 | 价格展示是否含税、发票与会计 |
| 关税（跨境） | **DDU**（买家到付）· **DDP**（卖家预收） | 结账文案必须写明，否则会有大量弃单与纠纷 |

> 工程侧不能替你定这些——这是业务与税务决策（bootstrap「不该发生」：不臆定税费与退换货规则）。

## 4. 退换货：与库存联动的关键一问

规则必须能落到 `04` 的四事件表上：

| 场景 | 库存怎么处理 | 需要站长先定 |
|---|---|---|
| 未发货取消 | 回补 | — |
| 仅退款（货未出） | 回补 | — |
| 退货退款（已发货） | 收到货并验收后回补 | 退货窗口（Q-23） |
| 退款不退货（破损补偿） | **不回补** | — |
| **孤品退款** | **Q-12：回补 / 不回补二选一** | 直接决定 `m-1c` 代码分支 |
| **孤品是否可退** | **Q-13：不接受 / 7 天可退 / 仅质量问题** | 决定政策文案与退款流程 |

卫生相关：**耳饰能否退货**需单独确认（Q-28），很多市场对耳饰有卫生限制。

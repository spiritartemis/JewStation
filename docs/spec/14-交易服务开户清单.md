## 1. 订单与库存存储 —— 已用 WorkBuddy 云数据库解决（无需开户）

**结论**：不再需要 Upstash / Neon / Supabase 开户。订单、库存、支付幂等键、邮件 outbox
四张表都建在**本应用自带的 WorkBuddy 云数据库**（Postgres）里，随应用走，账号和额度都是现成的。

**为什么它够用**：孤品「不超卖」需要原子扣减。这里用数据库事务而不是 Redis 脚本：
`jew_reserve_stock()` 在一个事务里 `SELECT ... FOR UPDATE` 锁行 → 全量校验 → 全量扣减，
任意一件不足就一件都不动。并发实测 25 单抢 20 件，成功 20 / 缺货 5，没有超卖。

**安全边界**（比 Redis 方案更严）：
- 四张表全部开启 RLS，且**不给 anon 任何策略** —— 匿名角色直接读表只会拿到空、改表直接被拒。
- 唯一入口是 `SECURITY DEFINER` 函数，订单读取/改状态**必须同时给出 accessToken**。
- 口令错与订单不存在返回同一个空值，无法用来探测订单号。

**连接参数在哪**：`src/lib/cloud.ts`（`endpoint` + `publishableKey`）。这两个是开通时下发的
**公开配置**，不是密钥，可以随代码入库；真正的边界由服务端 Origin 校验 + RLS 保证。
要换环境时用 `WORKBUDDY_CLOUD_ENDPOINT` / `WORKBUDDY_CLOUD_PUBLISHABLE_KEY` 覆盖。

**表与函数清单**（都在 `public` schema，前缀 `jew_`）：

| 对象 | 用途 |
|---|---|
| `jew_stock` | 每个 slug 的实时库存，首次下单时用商品数据的 stock 播种 |
| `jew_orders` | 订单主表，金额与商品快照冻结在下单时刻 |
| `jew_payment_keys` | 支付回调幂等键（主键冲突即「已处理过」） |
| `jew_mail_outbox` | 未接发信服务商时的邮件暂存 |
| `jew_reserve_stock` / `jew_release_stock` | 原子预占 / 回补 |
| `jew_put_order` / `jew_get_order` / `jew_set_order_status` | 订单写入 / 带口令读取 / 带口令改状态 |
| `jew_claim_payment_key` / `jew_append_outbox` / `jew_read_stock` | 幂等键 / 写 outbox / 库存快照 |

**验证方式**：下单后重启服务，再打开确认页链接，订单仍在 → 说明已经落库而不是在内存里。
页面上也不会再出现「演示模式」提示。

## 2. 支付服务商（支付）

**现状**：`src/lib/orders.ts` + `/api/pay/mock` 已按真实网关的三条纪律写好
（幂等键、订单归属性校验、不静默失败），换 provider 只需要替换 `payment.provider` 与那一个回调端点。

**Stripe（建议主选）**：
1. 注册 <https://dashboard.stripe.com/register>，先留在 **Test mode**
2. Developers → API keys → 复制 **Secret key**（`sk_test_...`，不要用 publishable 那支做服务端）
3. Developers → Webhooks → Add endpoint：`https://<你的域名>/api/pay/stripe`
   订阅 `payment_intent.succeeded` / `payment_intent.payment_failed` / `charge.refunded`
4. 复制 **Signing secret**（`whsec_...`）

| 变量名 | 说明 |
|---|---|
| `STRIPE_SECRET_KEY` | 服务端调 API 用 |
| `STRIPE_WEBHOOK_SECRET` | 校验回调确实来自 Stripe |

**PayPal（备选）**：Developer Dashboard → Apps & Credentials → Sandbox → 拿 Client ID / Secret。

**开户前必须先定的**（Q-34）：收款主体是公司还是个人、注册在哪个国家 —— 这决定 Stripe 能不能开。
不支持的话备选 PayPal，再不行就先上「不收款的预览站」（08 §7 回退方案）。

## 3. 发信服务商（交易邮件）

**现状**：三类模板已写好（下单确认 / 发货通知 / 退款取消），HTML + 纯文本双版本，
见 `src/lib/email.ts`。没有服务商时邮件写入 `mm:mail:outbox` 并打日志 —— 不静默失败。

**Resend（建议）**：
1. 注册 <https://resend.com>，Domains → Add Domain，按提示加 DNS 记录
2. 等验证通过（SPF / DKIM / DMARC 全绿，通常几分钟到几小时）
3. API Keys → Create，复制 `re_...`

| 变量名 | 说明 |
|---|---|
| `RESEND_API_KEY` | 发送用 |
| `MAIL_FROM` | 必须与已验证域名一致，如 `orders@yourdomain.com` |

**为什么必须用自有域名**：用服务商默认发信域（如 `onboarding@resend.dev`）只能给自测邮箱发，
正式用户收不到，且极易进垃圾箱。

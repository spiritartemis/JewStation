## 1. 站点定位与信息架构原则

- 定位：手工饰品 + 流行饰品的**移动端优先**独立站，先做「能看、能找、能买」，不做社区与内容矩阵。
- 架构原则：
  1. **三层封顶**：首页 → 列表/集合 → 详情，任何页面最多 3 次点击可达。
  2. **商品是主干**：列表与详情是转化主路径，导航不得抢戏。
  3. **政策页不进主导航**：只出现在页脚与结账/同意条（合规需要，但不是购物路径）。
  4. **购物车常驻**：移动端顶栏右侧常驻购物车入口，带数量角标。

## 3. 导航结构

### 3.1 移动端（主口径）

底部/顶部二选一，V0.1 采用**顶部精简栏 + 汉堡抽屉**：

```
[ ☰ ]        BRAND        [ 🛒 (n) ]

☰ 抽屉展开：
  · Shop 全部商品        → /shop
  · 分类
      - Earrings         → /collections/earrings
      - Necklaces        → /collections/necklaces
      - Rings            → /collections/rings
      - Bracelets        → /collections/bracelets
  · 风格
      - Minimal          → /collections/style-minimal
      - Vintage          → /collections/style-vintage
      - Statement        → /collections/style-statement
  · One of a Kind（孤品）→ /collections/one-of-a-kind
  · About               → /about
  · FAQ                 → /faq
```

- 搜索入口：顶栏搜索图标，展开为全屏搜索（`/search?q=`）。
- 购物车：常驻顶栏右，角标显示件数；空车点击进入空状态页。

### 3.2 桌面端（同一套结构，横向展开）

```
BRAND     Shop   Earrings   Necklaces   Rings   Bracelets   One of a Kind   About   FAQ        [🔍] [🛒(n)]
```

### 3.3 页脚（全站一致）

| 分组 | 链接 |
|---|---|
| Shop | 全部商品 · 新品 · 孤品 · 流行款 |
| Help | FAQ · 配送说明 · 退换货政策 · 联系客服（mailto） |

## 4. URL 与命名规则

- 全站小写、连字符分隔：`/products/silver-wave-hoops`
- 集合页 slug 由标签字典生成，标签 slug 与集合 slug 一致（避免两套命名）
- 商品 slug = 英文标题 slug 化；**slug 一经发布不得更改**（改则留 301 跳转）
- 政策页固定路径，不随语言/市场变化

---

## 5. 页面状态清单（每个页面都要有）

每个页面必须有这 4 个状态设计，否则 m-1b 实现时会漏：

1. **正常态** · 2. **空态**（无商品 / 无结果 / 空购物车） · 3. **加载态**（骨架屏，不跳动） · 4. **错误态**（加载失败可重试）

其中**孤品售罄态**是硬要求：孤品成交后显示「Sold」并不可加购（由 m-1c 服务端保证，前端只做展示）。

# 04 · 孤品与可补货商品状态流转（V0.1 · 0.1-04）

> 里程碑 `m-1a` / 需求 `R-jew-1a-2` / 任务 `T-jew-1a-2-01`
> 判据：孤品库存 = 1；下单锁定 / 付款成功 / 取消 / 退款等状态如何影响库存需明确；成交后不可继续购买。
> **B-1.5**：孤品记录库存恒为 1，任何 `stock > 1` 不得标记为孤品。
> **B-1.6**：四事件各自对库存的影响必须逐条写明，并被 `m-1c` 的实现**直接引用**。
> 状态：**草案 · 含 2 项须站长拍板（Q-12 / Q-13）**

---

## 1. 角色与对象

| 对象 | 说明 |
|---|---|
| `stock` | 可售库存数（孤品恒 1） |
| `reserved` | 已被未支付订单锁定的数量 |
| `available` | 可买数量 = `stock − reserved`（派生，不落库） |
| 订单状态 | `pending`（待支付）→ `paid`（已支付）→ `fulfilled`（已发货）→ `completed`；异常支线 `cancelled` / `refunded` |

---

## 2. 四事件对库存的影响（B-1.6 核心表）

| 事件 | 触发时机 | `stock` | `reserved` | `available` | 商品展示 | 备注 |
|---|---|---|---|---|---|---|
| **① 下单锁定** | 创建订单、进入支付前 | 不变 | `+1` | `−1` | 详情页显示「Reserved」（不可再锁定） | 锁定时长 = 支付会话有效期，**建议 30 分钟**；超时自动释放 |
| **② 付款成功** | 支付回调确认 | 孤品 `1→0`；可补货款 `−N` | `−1` | 孤品 `0` | 孤品 → **Sold**（永久不可再购）；可补货款库存减少 | 库存扣减必须是**服务端原子操作** |
| **③ 取消** | 未支付取消 / 锁定超时 | 不变 | `−1` | `+1` | 回到可售 | 孤品恢复为可买 |
| **④ 退款** | 已支付后退款 | **见 Q-12**：回补或不回补 | 不变（已清） | 随 `stock` | 孤品回补则重回可售；不回补则保持 Sold | 退款与退货是两件事，见 §4 |

### 2.1 库存口径硬规则

1. **孤品 `stock` 恒为 1**（B-1.5），售出后 `stock=0`、`status` 保持记录不删除，详情页永久显示 Sold。
2. **不超卖必须由服务端保证**（`m-1c` 实现）：并发下单时用数据库事务/唯一约束做原子扣减；**前端隐藏按钮不算数**。
3. `available` 由 `stock − reserved` 派生，**不落库**，避免双写不一致。
4. 锁定（reserved）**必须有超时释放**，否则未支付订单会把孤品永久锁死。
5. 加购（加入购物车）**不锁库存**，只有进入结账创建订单才锁（否则购物车会被用来占货）。

---

## 3. 锁定超时（建议值，待确认）

| 项 | 建议值 | 说明 |
|---|---|---|
| 支付锁定时长 | **30 分钟** | 太短伤体验（填地址慢），太长锁死孤品 |
| 释放方式 | 定时任务 + 支付回调兜底 | 双保险：回调先到则以回调为准 |
| 同一商品重复锁定 | 禁止（`available=0` 时不可创建订单） | 直接拒绝，不排队 |

---

## 4. 退款 vs 退货（口径必须分开）

| 场景 | 库存处理 | 说明 |
|---|---|---|
| **仅退款（未发货 / 取消）** | 回补库存 | 货未出，商品还在手上 |
| **退货退款（已发货后退回）** | 回补库存（验收通过后才回补） | 需收到货并确认可二次销售 |
| **退款不退货（如破损补偿）** | **不回补** | 商品未回库 |
| **孤品退货** | 见 Q-12：回补则重回可售 | 手工孤品是否接受退货本身也是政策问题（Q-13） |

> 回补动作一律在**服务端事务**内完成，并与订单状态机联动，不得手改库存。

---

## 5. 孤品 vs 可补货款对照

| 环节 | 孤品 `one_of_a_kind` | 可补货款 `restockable` |
|---|---|---|
| 初始库存 | 1 | N |
| 加购 | 允许（不锁） | 允许（不锁） |
| 创建订单 | 锁 1 | 锁 N |
| 支付成功 | 扣至 0 → Sold | 扣 N |
| 锁定超时 | 释放，恢复可售 | 释放 |
| 取消（未付） | 恢复可售 | 恢复 |
| 退款 | 按 Q-12 | 回补（除非退款不退货） |
| 售罄展示 | **Sold** · 不可加购 · 记录保留 | Out of stock · 可补货后续上架 |
| 推荐与列表 | 排除（`m-1d`） | 按库存展示 |

## 6. 状态机图（m-1c 实现依据）

```
                  ┌─────────── 锁定超时 ───────────┐
                  ↓                                │
  [可售 available=1] ──①创建订单(锁)──▶ [已锁定 reserved=1]
                                            │
                              ┌─────────────┼─────────────┐
                          ②支付成功      ③取消/超时       （无操作）
                              ↓              ↓
                     [已售 sold stock=0]  [可售 available=1]（释放）
                              │
                          ④退款
                              ↓
                   Q-12=回补 → [可售]  /  Q-12=不回补 → [保持 Sold]
```

| 编号 | 问题 | 选项 | 不确定的后果 |

| **Q-12** | 孤品退款后是否回补库存（重新变为可售）？ | A 回补（货在手上就能再卖）· B 不回补（售出即终结，避免纠纷） | 直接决定 `m-1c` 退款分支的库存代码；不定则退款流程无法落地 |

## 2. 邮箱订阅（`1.0-06` · m-1d）

工程侧已定的实现口径（待站长确认用途后即可落地）：

| 项 | 口径 |
|---|---|
| 收集字段 | 仅邮箱（+ 同意记录：时间、来源页、用途） |
| 校验 | 格式校验 + 双重确认（double opt-in 更稳妥，看市场要求） |
| 重复订阅 | 幂等：已订阅则提示「已订阅」，不重复发欢迎信 |
| 退订 | 每封邮件底部退订链接；退订即时生效并记录 |
| 用途说明 | 表单旁必须写明「会收到什么、多久一次」（合规要求） |
| 数据源 | 与交易邮件**同一家服务商**（`08` §1，Q-36），便于域名验证与退信处理 |

**待站长定**：是否要 double opt-in（Q-48）——GDPR 区域强烈建议，其他区域可单重确认。

## 3. 是否要求注册

| 方案 | 优点 | 成本 | 工程侧建议 |
|---|---|---|---|
| **访客结账（推荐）** | 转化路径最短，无密码摩擦 | 订单靠邮箱+订单号查询 | ✅ V0.1 采用 |
| 强制注册 | 便于营销与订单历史 | 增加流失、需账户体系与找回密码 | ❌ 不建议起步就做 |
| 可选注册（下单后可设密码） | 折中 | 额外开发 | 可放 V1.1 评估 |

## 5. 与推荐/追踪的关系（合规要点）

- 订阅（营销）与浏览追踪（个性化）是**两件事**，需要**分别同意**。
- 未同意个性化追踪时，首页推荐位回落「新品/爆款」（`1.0-05` 已定）。
- 订阅表单的同意记录与 Cookie 同意记录分开存，便于撤回与审计。
